# Research requirements and current coverage

This matrix compares the current repository with the supplied `MODIS VIIRS PROJECT` research PDF and the two implementation briefs. The PDF covers a broader scientific platform than the first live-data slice. A common map grid is a spatial alignment step; it does not by itself make MODIS and VIIRS measurements equivalent.

| Requirement | Current state | Evidence / remaining work |
|---|---|---|
| NASA FIRMS as primary source; MODIS and VIIRS 375 m | First live sample complete | Authenticated availability and bounded Area API requests were verified. Non-empty MODIS_NRT and VIIRS_NOAA21_NRT CSVs are archived for Prainha, Brazil, with matching checksums and validated row counts (8 MODIS, 69 VIIRS); all 77 rows are committed to PostGIS and returned by the map API. Historical ingestion and recurring reconciliation remain. |
| NRT for recent monitoring; standard science-quality data for historical analysis | Partial | Current retrieval selects NRT products only. Standard products and NRT-to-standard reconciliation are not implemented. |
| Preserve original records, sensor identity, timestamps, quality and provenance | Partial | Binary-safe CSV archives, matching SHA-256 manifests, archive checksum/size/count validation on replay, raw source fields, UTC timestamp, sensor/product metadata and idempotent observation key are implemented. Invalid-row counts and source record IDs need richer tracking. |
| PostgreSQL + PostGIS storage and spatial indexing | First live sample complete | Docker Desktop runs `postgis/postgis:16-3.7`; PostGIS 3.7.0 is ready and Alembic revisions 0001–0004 are applied. Both source files and their 77 observations are stored with provenance; spatial filters were verified through the API. Region/grid population and aggregate calculations remain. |
| Select region, bounding box, dates and sensors | Partial | API and dashboard support date and bounding-box filters plus sensor selection. Empty filters now stay empty once live observations exist, instead of falling back to unrelated fixtures. Country and polygon selection, latitude/longitude search and density mode remain. |
| Daily, monthly, yearly and historical calendar | Partial | Daily/monthly/yearly API and UI views work on available observations. A multi-year month-by-month heatmap, seasonal summaries, and historical coverage indicators need standard data. |
| Sensor comparison | Partial | Separate counts, FRP summaries and source confidence categories are displayed. Matched-period spatial/day-night distributions, opportunity normalization, and validation are not implemented. |
| Spatial grid and reusable regional/daily aggregates | Schema foundation | Grid-cell and sensor-aggregate tables/indexes are migrated; grid selection, cell population, and aggregate calculations remain. |
| MODIS–VIIRS harmonization | Sensor-specific spatial/temporal layer implemented; calibration pending | Raw rows promote idempotently into point observations, daily sensor aggregates, and versioned common-grid activity. Annual verification checks eligible source identities, recomputed daily counts/FRP/day-night statistics, harmonized activity values, and provenance before collection advances. The separate team research document defining cross-sensor calibration was not supplied; raw counts are not presented as measurement-equivalent. |
| Historical baselines and anomalies | Filtered elementary summary screen implemented; formal baselines pending | The regional summary and `/anomalies/summary` accept sensor/date/area filters and compare the last bucket only when at least six consecutive observed monthly buckets are present. Missing months suppress the calculation and remain unknown, not zero. Baseline and anomaly tables exist but remain empty; the stored historical coverage is incomplete and no formal seasonal score is claimed. |
| CSV and PDF reports with provenance and job history | Partial | Reports UI now exposes sensor/date/bounding-box filters. A filtered 77-row CSV and PDF were generated from PostGIS; the PDF job was tracked. Regional/monthly/chart exports remain. |
| Resumable historical ingestion and recurring checks | Implemented; intentionally paused | Durable global queue, availability-based annual product planning, 1–5 day chunks, archived CSV/database payload, committed-range reconciliation on explicit resume/crash recovery, and rolling sync are implemented. Collection is opt-in and year-gated behind harmonization verification; resume after frontend acceptance. |
| Optional LLM explanations | Backend integration implemented; credentials required | Region summary and NASA Worldview imagery link are available. An OpenAI-compatible LLM explains the computed summary when LLM_BASE_URL, LLM_API_KEY, and LLM_MODEL are configured; deterministic 13-line summaries work without an LLM. |
| Deployment, monitoring, backups and performance checks | Not started | Local run instructions exist; deployment and operations setup are not verified. |

## First real-data acceptance gate

**Passed for the first live sample (2026-11-13):** the project retrieved one MODIS_NRT and one VIIRS_NOAA21_NRT source CSV from FIRMS, verified both archived file checksums, validated 8 and 69 rows, committed all 77 observations to PostGIS, confirmed sensor-filtered map API responses (8 and 69), and generated a 77-row filtered CSV plus a PostGIS-tracked PDF report. The visible browser map remains to be checked. This gate does not imply historical, harmonization, or anomaly requirements are complete. Synthetic fixtures and mocked network tests do not satisfy this gate.
